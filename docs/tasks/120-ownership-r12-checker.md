- **Mission:** SITE-V1, deliverable **D2** — **Status:** spec-approved (manager, 2026-11-26, after independent spec review round 1 = PASS-WITH-FINDINGS, all eight findings folded in; security: CI gate)
- **Repo:** registry. **Agent / model:** implementer (model per frontmatter). **Budget:** medium (≤ 3 agent-sessions)

- **Graph:** N3, edge E16. **Supersedes:** the unmerged remainder of 008b-3a (its branch `487a4cb` stays as a reference and is never rewritten or merged). **Blocks:** 008b-3b.
- **Why:** 008b-3a was built to a carve-out the contract did not have (F1). Task 118 wrote the contract (`R12`, `I9`); the checker and its tests must now implement exactly that text. 118's decision: contract and checker merge as **one PR** after one sweep, because `tests/registry/test_ownership_mutations.py` asserts the rule counts and a test pair per rule.

## Objective
`tools/registry/ownership.py` and `tools/registry/ci_gate.py` implement `contracts/ownership.md` `R12` and `I9` as written on the 118 head, replacing the fail-closed rejection of every T1/T3 PR with: authorised iff `R12` authorises; otherwise rejected by `R12`. `config/pipeline-identity.json` exists with `"pipeline_identity": null` (so `R12` authorises nobody until 008b-3b sets the id). The test suite covers `R12` and `I9` both ways, and the registry gate is green on the combined head.

## Decisions (manager ★ under ADR-0125, 2026-11-26)
- **Re-cut, written fresh to the contract.** A★ implement from the merged contract text, using `git show 487a4cb` (and its parents `dbbd983`, `827c562`, `bd203e0`) only as a reference; B cherry-pick 008b-3a and patch. Reason: 008b-3a's design differs (it took a `pipeline_identity` argument with no config file, had a dead `pipeline_app_id`, and no `I9`), and its review found five defects (F2-F6); patching a mismatched design is how F1 happened.
- **Configuration path mirrors `R11`:** `ci_gate.py` gains `read_pipeline(old)` with the rules `R12` states (same as `read_r11`: absent = None; symlink, non-file, malformed, wrong key set or version, provider not `"github"`, id not `type(id) is int and id > 0` = `Undecided`), materialises `config/pipeline-identity.json` at merge-base beside `r11-identity.json`, and passes it to `tools/registry/ownership_cli.py` as a new `--pipeline-identity PROVIDER:ID` flag beside `--r11-identity`, which the CLI passes into `check()`. The CLI keeps the three `--help` strings `007b-verify.sh` greps (its L102-104). **`I9` at both layers:** `ci_gate` returns `Undecided` (exit 2) when both identities are configured and equal; `ownership.check()` and the CLI raise `ToolError` (exit 2, not a rejection) for the same pair, also on a direct call (F5). `registry-ci.yml` needs no change (reviewer-verified: it calls `ci_gate.py` generically); the only materialise change is ci_gate.py's allow-list (~L311).
- **`pipeline_app_id` is removed** (F4); nothing replaces it but the configured identity.

## Acceptance criteria
1. [script] **Accept:** a PR authored by the configured pipeline identity whose change is exactly one T1, and one whose change is exactly one T3, each on `test:hello-world` (reserved) and on an ordinary namespace, are accepted by the ownership check (fixtures built with `tests/registry/support.py`'s helpers, element shapes taken from 057's oracle fixtures). For the reserved case the membership oracle raises if called, and the test asserts it was **not** called (`R7`/`R9` not consulted). A byte-different but parsed-equal `entry.json` (whitespace, key order) around the T1 still accepts.
2. [script] **Reject by `R12`, each shown:** the same diffs by a different id; by an id whose login matches the bot's but id differs (the 007 hostile pattern); with `pipeline_identity` unconfigured (null, and file absent); a T1 plus a new version; a T1 plus a `page.json` edit; a T1 plus an extra top-level key in `entry.json` (F3); two T1s; a T1 and a T3; a T1 and a takedown (also rejected by `R11`); a T3 with blank `reason` or a non-`https://` `build_log_url`; a T1 on one `entry.json` plus any change to another file (`config/`, `contracts/`, `.github/`, another mod); a newly added element born `published` or `rejected`, including by the namespace's own owner (057 attack 1); an `entry.json` that does not parse or has a duplicate key while a T1/T3 is present; a T1 that `append_only` does not classify as T1 (e.g. a pipeline field missing); a T1 that also changes `id` or `owner`; a T1 that also changes another element; two `entry.json` files each with a T1; the pipeline identity changing an already-`published` element (not a T1). **Every one of these rejections carries the rule tag `R12`** (asserted on the finding, so a leftover `fail-closed` tag fails), plus `R11` where stated. `R2` and `R10` still reject an otherwise-authorised write-back (id/directory mismatch; `page.json` with no entry). Positive control: an owner's ordinary new-version PR still accepts; the 007 hostile fixtures still reject.
3. [script] **Configuration (ci_gate):** absent file -> unconfigured; `null` -> unconfigured; `{"provider":"github","id":342916936}` -> configured; symlink, directory, malformed JSON, extra key, wrong `schema_version`, provider `"gitlab"`, id `"342916936"`, `true`, `0`, `-1` -> `Undecided` (exit 2, not a rejection); the file is read from the merge-base, so a PR that edits it and carries a T1 is judged by the merge-base value. 4. [script] `config/pipeline-identity.json` = `{"schema_version": "1.0.0", "pipeline_identity": null}` with a trailing newline, matching `r11-identity.json`'s style.
