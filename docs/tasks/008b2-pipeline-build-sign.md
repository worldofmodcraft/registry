## Build-result handoff (interface to 008b-3b; this part owns it; manager ★, session 12)
008b-3b's write-back job reads only what this section lists. The layout is produced by `tools/pipeline/handoff.py` (new, with `sign_built.py`) and by the workflow's upload steps, and is checked by criterion 26.
- **Matrix.** The build job runs one matrix leg per entry of the plan's `build` list, with `strategy.fail-fast: false`, so one version's fault never stops the others (PT5). Entries of the plan's `refuse` list, `skip` list and `fault` list get no leg; the write-back job reads them from the plan document (artifact `plan`, the planner's JSON, uploaded by the plan job).
- **Per-version build artifact `build-<tag>`** (`<tag>` = the release tag of `artifact-naming.md`), uploaded by the leg whatever its exit code. **What 008a leaves behind (read 2026-10-26 from `build_version.py` and `pipeline_errors.py` in the read-only 087+082 merge checkout, not from registry `main`; the registry `main` text is [unverified] to match):** exit 0 writes the tarball (and signature, absent under `--no-sign`), `result.json` and `build.log`; exit 1 and exit 2 write **`build.log` only, and only if the build had started**; a pre-flight failure leaves `--out` untouched and prints on stderr only. So the artifact holds `outcome.json`, `build.stderr` (the leg's captured stderr), and: for exit 0 `<tag>.tar.gz`, `result.json` (`signed: false`), `build.log`; for exit 1 and 2 `build.log` when present (no `result.json`, no tarball). `outcome.json` is written by `handoff.write_outcome()` and has the fields `version_id`, `tag`, `exit_code` (0 built, 1 rejected by 008a, 2 pipeline fault), `reason`. **`reason` (manager ★, session 12):** for exit 1 it is taken from 008a's `Rejected.__str__` line `REJECTED [<rule>]: <message> -- remedy: <remedy>`, read first from `build.stderr`, else from the last `result: exit 1 ` line of `build.log`; `reason` is that line without the `REJECTED ` prefix (so `[<rule>]: <message> -- remedy: <remedy>`), with whitespace runs collapsed to single spaces and trimmed; no other truncation is applied here (the full text is in the committed log), and if the result is empty after trimming — the schema's `reason` rule — the version is an exit-2 fault. For exit 0 and 2, `reason` is empty. The archive log that 008b-3b commits is `build.log` when present, else `build.stderr`.
- **Per-version signed artifact `signed-<tag>`**, uploaded by the signing job only for exit-0 legs: `<tag>.tar.gz`, `<tag>.tar.gz.minisig`, `result.json` with `signed: true`, `artifact.signature`, `artifact.key_id`, and `outcome.json` unchanged. **Any re-verification failure in the sign step (tampered tarball, size or entry limit, sha mismatch, `reference_verify` failure) is written as an updated `outcome.json` with `exit_code` 2 (a pipeline fault, manager ★, session 12)**, with no signature: only 008a's own exit 1 is a rejection of the author's version. `sign_built.py` may keep its own named refusal exit for its direct tests (criterion 16); the handoff layer maps every such refusal to 2.
- **How each kind reaches 008b-3b:** built and signed -> `signed-<tag>` (exit 0); rejected by 008a -> `build-<tag>` with `outcome.json.exit_code == 1`; pipeline fault -> `build-<tag>` (or `signed-<tag>`) with `exit_code == 2`, or no artifact at all (a leg killed) — the write-back job treats a plan `build` entry without any artifact as exit 2; `+` refusal, skip and schema fault -> the `plan` artifact only.
- **Job conditions (manager ★, session 12).** The plan job exports two outputs computed by `handoff.plan_flags(plan)`: `has_build` (the plan's `build` list is non-empty) and `has_writeback` (`build` or `refuse` is non-empty). The **build** job runs only when `has_build` is true, so GitHub is never given an empty matrix (that GitHub rejects an empty matrix is [unverified]; the conditions make the question moot). The **sign** job has `needs: [plan, build]` and `if: always() && needs.plan.result == 'success' && needs.plan.outputs.has_build == 'true'` (so one failed build leg does not skip it), and each sign leg has a **per-version guard**: it proceeds only when that version's `build-<tag>/outcome.json` has `exit_code == 0`, otherwise it succeeds doing nothing. The **write-back** job (added by 008b-3b) has `needs: [plan, build, sign]` and `if: always() && needs.plan.result == 'success' && needs.plan.outputs.has_writeback == 'true' && github.ref == 'refs/heads/main'`, and processes each version by the kinds above. Zero pending versions give `has_build` and `has_writeback` both false: the run ends green having written nothing (umbrella criteria 12 and 27). The **summary** job runs `always()`; while the push gate is in force its condition is `always() && github.event_name != 'push'`, and the run's final colour is the summary's.
- `handoff.read_outcomes(dir)` is the one reader 008b-3b imports; no other code parses these files.
